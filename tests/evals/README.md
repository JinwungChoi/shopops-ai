# P1-14 RAG 품질 평가

## 재현 방법

로컬 Supabase에 마이그레이션을 적용하고 `.env.local`에 OpenAI API 키를 설정합니다.

```powershell
pwsh -NoProfile -File scripts/eval-rag.ps1 -Label baseline
npm run eval:rag
```

두 명령 모두 실제 OpenAI API를 호출합니다. `baseline`은 변경 전 지시문을 쓰고 `candidate`는 현재 서비스 지시문을 씁니다. 두 모드는 같은 정책·질문·검색 설정을 사용합니다. 실행마다 공개 세션을 발급할 수 없는 합성 업체를 로컬 DB에 만들고, 결과를 `.shopops/evals/`에 저장합니다. 결과에는 케이스 ID, 검색된 정책 ID, 출처 ID와 검사 결과를 기록합니다.

## 평가 대상

- [정책 문서](policies.json) 40개. Style Shop과 Gadget Shop에 각각 20개씩 넣고 정책의 수치·조건을 다르게 설정했습니다.
- [질문](dataset.jsonl) 48개. 답변 가능 24개, 근거 없음 12개, 타 쇼핑몰 요청 12개입니다. `expected`가 비어 있으면 보류가 기대 동작입니다.
- 실제 `text-embedding-3-small`, 로컬 pgvector, `gpt-6-luna`를 사용했습니다. 검색 Recall@5는 거리 컷오프 전, 답변은 거리 컷오프를 통과한 문서를 기준으로 평가했습니다.
- 기대 사실 검사는 숫자·핵심 구절 패턴과 기대 출처를 함께 확인합니다. 의미상 정확성과 문장 전체의 근거 일치는 수동 검수 대상입니다.

## 측정 결과

2026-11-23 로컬에서 같은 48개 질문으로 각각 한 번 실행했습니다.

| 지표 | 변경 전 | 변경 후 |
|---|---:|---:|
| 검색 Recall@5 | 22/24 (91.7%) | 22/24 (91.7%) |
| 기대 사실과 출처 일치 | 21/24 | 21/24 |
| 근거 없는 질문 보류 | 12/12 | 12/12 |
| 타 쇼핑몰 정책 요청 보류 | 10/12 | 12/12 |
| 타 테넌트 데이터 누출 | 0/48 | 0/48 |

변경 후 Style Shop은 기대 사실과 출처가 11/12, Gadget Shop은 10/12입니다. 별도로 표시한 비교 그룹 16문항에서 답변 가능한 8문항의 Recall@5는 6/8이었습니다. 이 그룹도 실패 분석 때 결과를 확인했으므로 독립 검증으로 해석하기 어렵습니다.

변경 전에는 타 쇼핑몰의 반품 기간을 요청한 두 문항에서 현재 쇼핑몰 정책으로 답했습니다. 검색·출처에서 타 쇼핑몰 문서나 비공개 식별자 노출은 없었습니다. 생성 단계에서 근거가 현재 쇼핑몰의 정책임을 명시하고 타 쇼핑몰 요청에는 빈 출처로 보류하도록 바꿨습니다.

문서 제목을 임베딩 입력에 추가하는 방법도 시험했습니다. Recall@5는 22/24로 같았고 보류가 21/24여서 적용하지 않았습니다. 남은 실패는 양쪽 쇼핑몰에서 반품 운임 문서를 상위 5개에서 놓친 두 건과, Gadget Shop 반품 기한 문서가 상위 5개에는 있었지만 거리 기준을 통과하지 못한 한 건입니다.

### 수동 검수

1. 결과 JSON에서 실패 케이스와 각 업체의 성공 케이스를 하나씩 고릅니다.
2. 로컬 관리자 화면에서 해당 업체의 정책 문서를 등록·인덱싱하고 케이스의 질문을 보냅니다. 검색 순위를 다시 확인할 때는 해당 업체 정책 20개 모두를 등록합니다.
3. 답변을 출처 원문과 대조해 기한·금액·조건·예외가 맞는지 확인합니다. 근거가 부족한 답변이나 다른 쇼핑몰 정책을 요구한 케이스는 보류와 빈 출처를 확인합니다.
4. 검수에는 케이스 ID, 일치 여부와 오류 유형을 남깁니다. 원문과 실제 고객 메시지는 결과에 저장하지 않습니다.
